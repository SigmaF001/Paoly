## ผลตรวจและข้อจำกัด

- `flutter analyze --no-pub`: ผ่าน ไม่มี issues ตาม configuration ปัจจุบัน ซึ่งไม่รวมโฟลเดอร์ native platform
- `flutter test --no-pub`: ไม่ผ่าน 1 test; `test/widget_test.dart:22` คาดหวัง `฿ 48,320.50` แต่สร้าง FinanceData ว่าง ไม่มี fixture ยอดดังกล่าว
- ทดสอบจำลองเฉพาะจุด 6 กรณี: ยืนยันพฤติกรรมผิดได้ครบ 6 กรณี (assert ผลผิดที่เกิดอยู่ ไม่ใช่ regression tests ที่ยืนยันว่าบัคถูกแก้แล้ว)
- ทดสอบ OCR ผ่าน public `processImage` โดย mock native channels ให้ส่งข้อความที่กำหนด จึงยืนยัน parser ไม่ใช่ความแม่นยำของ OCR จากภาพจริง
- สคริปต์ตรวจ UI แบบ static ของ frontend-design-premium ไม่พบ findings แต่ไม่ได้พิสูจน์ว่า Flutter UI ผ่านการทดสอบการเข้าถึงหรือทุกสถานะการใช้งาน
- ยังไม่ได้ build แอพ native หรือทดสอบบนอุปกรณ์จริง รวมถึงสิทธิ์กล้อง สลิปจริง การเข้าถึง และ layout หลายขนาด
- เก็บ probe ชั่วคราวที่ `/tmp/paoly_audit_probe_test.dart` และผล static audit ที่ `/tmp/paoly-premium-audit.json` ไฟล์ชั่วคราวอาจถูกระบบลบ

## บัคเรียงตามความสำคัญ

### 1. P1 — ข้อมูลการเงินหายเมื่อเริ่มแอพใหม่

หลักฐาน: `lib/data/finance_data.dart:98`, `lib/main.dart:15`.

บัญชี รายการ และหมวดหมู่กำหนดเองอยู่ใน List เท่านั้น ไม่มี save/load หรือ serialization ของโมเดลการเงิน ตอนเริ่มแอพสร้าง FinanceData ใหม่และ seed บัญชียอดศูนย์ มีเพียง settings กับข้อมูลน้องหมาที่โหลดจาก storage

จำลองเพิ่มบัญชี ตั้งยอด 500 และลงรายจ่าย 100 พบว่าไม่มีการเขียน preference ข้อมูลการเงิน และ FinanceData ใหม่เริ่มยอด 0 พร้อมรายการว่าง การจำลองนี้ประกอบกับการตรวจ startup ยืนยันช่องว่างการบันทึก ไม่ใช่การทดสอบ kill/relaunch บนอุปกรณ์จริง

ควรแก้: จัดเก็บข้อมูลการเงินถาวรพร้อม schema version และการบันทึกรายการกับยอดบัญชีให้สำเร็จร่วมกัน ทดสอบปิด process แล้วเปิดใหม่

### 2. P1 — อ่านยอดสลิปหลักพันที่ไม่มี comma ผิด

หลักฐาน: `lib/services/slip_scanner_service.dart:127`.

ทดสอบ `Amount 1234.56` ได้ `234.56` เพราะ regex รับตัวเลขก่อนจุดเพียง 1–3 หลักเมื่อไม่มี comma และไม่มีขอบเขตกันการจับท้ายตัวเลข ผู้ใช้ที่เชื่อค่าจากสลิปจะบันทึกยอดต่ำกว่าจริง

ควรแก้: parser ต้องรับทั้ง `1234.56` และ `1,234.56` พร้อมขอบเขตตัวเลขและตรวจความกำกวมของยอด/ค่าธรรมเนียม

### 3. P1 — วันที่สลิปผิดและส่งต่อไปยัง date picker นอกช่วง

หลักฐาน: `lib/services/slip_scanner_service.dart:213`, `:221`, `:228`, `:237`; `lib/widgets/add_transaction_sheet.dart:211`.

ยืนยันด้วยข้อมูลจำลอง:

- `29/05/69` → ค.ศ. 1526 แทน 2026 เพราะบวก 1457 แทนการแปลง พ.ศ. ให้ถูกต้อง
- `31/02/2026` → 3 มีนาคม 2026 แทนการปฏิเสธวันที่ไม่มีจริง; DateTime ปรับวันล้นให้เอง
- `10 มิ.ย. 2569` → null เพราะ regex ชื่อเดือนไม่รับสระ/เครื่องหมายไทยบางตัว

วันที่ปี 1526 ถูกกำหนดให้ `_selectedDate` แต่ date picker จำกัด 2020–2030 จึงละเมิดเงื่อนไข initialDate และเกิด assertion ใน debug เมื่อเปิดปฏิทิน เส้นทาง UI นี้เป็นผลจากโค้ด ยังไม่ได้จำลองกดจริง

ควรแก้: แปลงปีตามรูปแบบที่รองรับ ตรวจวันโดยเทียบค่าหลังสร้าง DateTime และตรวจช่วงก่อนนำเข้า picker

### 4. P1 — การเรียกกล้องบน iOS ขาด permission description

หลักฐาน: `ios/Runner/Info.plist`; `lib/widgets/add_transaction_sheet.dart:116`.

ไม่มี `NSCameraUsageDescription` และ `NSPhotoLibraryUsageDescription` ใน plist ขณะที่มีปุ่มเรียกกล้อง/คลังภาพ เอกสาร image_picker กำหนดให้เพิ่มค่าที่เกี่ยวข้อง เส้นทางกล้องจึงมีความเสี่ยงถูก iOS ยุติแอพ ยังไม่ได้ทดสอบบนเครื่องจริง

นอกจากนี้ `pickImage` อยู่นอก try/catch จึงไม่แสดง scanError เมื่อ plugin โยน exception ในขั้นเลือกภาพ และไม่มี mounted guard ก่อน setState หลัง await เลือกภาพ/อ่านสลิป

ควรแก้: เพิ่มคำอธิบายสิทธิ์ตามการใช้งานจริง ครอบคลุม error ตลอด flow และตรวจ mounted หลัง async ก่อนใช้ state/context

แหล่งอ้างอิง: https://pub.dev/packages/image_picker

### 5. P2 — ลบรายรับแล้วเหรียญไม่ถูกปรับคืน

หลักฐาน: `lib/data/finance_data.dart:162`; `lib/data/pet_data.dart:125`.

จำลองเพิ่มรายรับ 100 แล้วลบ: ยอดบัญชีกลับ 0 รายการว่าง แต่เหรียญเพิ่ม 1 จึงทำซ้ำเพื่อสะสมได้ นอกจากนี้รายรับบวกที่ต่ำกว่า 100 ทุกครั้งให้ขั้นต่ำ 1 เหรียญ ต่างจากคำอธิบายอัตราใน README และทำให้การแยกรายการได้รางวัลมากกว่า

ควรแก้: ผูกรางวัลกับ transaction ID และกำหนดกติกาการแก้/ลบ/Undo รวมถึงกรณีใช้เหรียญไปแล้วให้ชัดเจน ไม่ควรเพิ่มรางวัลใหม่ทุกครั้งที่คืนรายการ

### 6. P2 — หมวดหมู่รายงานผูกด้วยชื่อไทยแทน ID

หลักฐาน: `lib/widgets/add_transaction_sheet.dart:200`; `lib/screens/reports_screen.dart:27`; `lib/data/finance_data.dart:223`.

รายการบันทึกชื่อไทยและ icon แบบ snapshot แล้วรายงานรวมยอดด้วยชื่อนั้น เมื่อเปลี่ยนชื่อหมวดหมู่ รายการเก่าจะไม่ตามชื่อใหม่และรายการใหม่แยกเป็นอีกกลุ่ม หมวดหมู่ชื่อซ้ำถูกรวมกลุ่ม สลับอังกฤษก็ยังแสดงชื่อหมวดหมู่ไทย

ควรแก้: บันทึก categoryId แล้ว resolve ชื่อและ icon จากหมวดหมู่ รวมถึงกำหนดวิธีจัดการหมวดหมู่ที่ถูกลบ

### 7. P2 — ปัดลบรายการทันทีโดยไม่มีวิธีกู้คืนใน UI

หลักฐาน: `lib/screens/transactions_screen.dart:155`; `lib/screens/dashboard_screen.dart:528`.

ทั้งสองหน้าลบจาก onDismissed ทันที ไม่มี confirmDismiss หรือ Undo ผู้ใช้ที่ปัดพลาดต้องกรอกใหม่ และปัจจุบันไม่มีหน้ารายละเอียดสำหรับแก้รายการ

ควรแก้: เพิ่ม Undo ที่คืนรายการ ยอดบัญชี และรางวัลอย่างสอดคล้องกัน พร้อมทางเลือกลบที่ไม่ต้องใช้ gesture

### 8. P2 — ความสามารถสแกนที่ประกาศกว้างกว่าที่โค้ดรองรับ

หลักฐาน: `lib/services/slip_scanner_service.dart:21`; `lib/widgets/add_transaction_sheet.dart:444` โดยปุ่มสแกนไม่ได้แยกแพลตฟอร์ม.

ใช้ ML Kit Latin recognizer ซึ่งไม่ใช่ตัวอ่านภาษาไทย ชื่อผู้รับไทยและเดือนไทยจึงไม่ควรถูกประกาศว่ารองรับสมบูรณ์เพียงเพราะมี regex ภาษาไทย ส่วน plugin รองรับ Android/iOS ไม่รองรับ desktop/web แม้โครงการมี target เหล่านั้น

ควรแก้: แสดงความสามารถตามแพลตฟอร์ม มี manual fallback และทดสอบภาพจริงของธนาคารแต่ละแห่งก่อนระบุการรองรับ หากต้องอ่านไทยให้ประเมิน OCR ที่รองรับโดยคงเงื่อนไขความเป็นส่วนตัวของผลิตภัณฑ์

แหล่งอ้างอิง: https://pub.dev/packages/google_mlkit_text_recognition และ https://developers.google.com/ml-kit/vision/text-recognition/v2/languages

## ฟีเจอร์ที่ควรเพิ่มตามลำดับ

ข้อเสนอต่อไปนี้อิงช่องว่างในโค้ดและงานที่แอพต้องทำ ไม่ใช่ผลวิจัยตลาดหรือสิ่งที่ผู้ใช้อนุมัติให้พัฒนาแล้ว

| ลำดับ | ฟีเจอร์ | เหตุผลและขอบเขตเริ่มต้น |
|---|---|---|
| 1 | สำรอง/กู้คืน + export CSV | ทำหลัง persistence ถูกต้อง ให้ย้ายเครื่องและนำข้อมูลออกได้; ทดสอบ restore และป้องกันรายการซ้ำก่อนใช้ข้อมูลจริง |
| 2 | แก้ไขรายการ + Undo + ค้นหา/กรอง | แก้ยอด วันที่ บัญชี หมวดหมู่ได้ ค้นชื่อและกรองบัญชี/หมวดหมู่/ช่วงวัน โดยยอดบัญชีปรับตามทุกครั้ง |
| 3 | โอนระหว่างบัญชี | ลดบัญชีต้นทางและเพิ่มปลายทางในรายการเดียว ไม่รวมเป็นรายรับ/รายจ่ายและไม่สร้างเหรียญ |
| 4 | งบรายเดือนและเป้าหมายออม | งบต่อหมวด แสดงใช้ไป/เหลือ และความก้าวหน้าเป้าหมาย; เริ่มจากข้อมูลที่ผู้ใช้กำหนดเอง |
| 5 | รายการประจำและเตือนบิล | ให้ผู้ใช้ยืนยันรายการที่ถึงกำหนด มีป้องกันการสร้างซ้ำและจัดการวันที่สิ้นเดือนได้ |
| 6 | หน้าตรวจสลิปก่อนบันทึก + เตือนสลิปซ้ำ | แสดงภาพคู่ค่าที่อ่าน ไฮไลต์ค่าที่อ่านไม่ได้ ให้แก้ก่อนบันทึก; การตรวจซ้ำไม่ใช่การรับรองว่าสลิปแท้ |
| 7 | PIN/biometric lock + ตั้งค่าความเป็นส่วนตัว | เหมาะกับข้อมูลส่วนตัว แยกให้ชัดว่าล็อกหน้าจอไม่เท่ากับเข้ารหัสข้อมูลสำรอง |
| 8 | ภารกิจน้องหมาจากความสม่ำเสมอ | พิจารณารางวัลจากบันทึกประจำวัน/เป้าหมายที่กำหนด แทนการจูงใจให้เพิ่มรายรับสมมติ ต้องออกแบบกติกากันทำซ้ำก่อน |

ควรเริ่มรอบแรกด้วย persistence, parser ยอด/วันที่, permission และ lifecycle การสแกน พร้อมแก้ชุดทดสอบเดิม แล้วจึงเพิ่มฟีเจอร์แก้รายการ/Undo และสำรองข้อมูล
